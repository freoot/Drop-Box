# CMD-010 交接单 · hero005 武器真实挂接 + 可操作最小战斗

## 一、两句话结论

1. **武器**：hero005 原本没有独立武器对象，武器是并进角色网格、蒙在 `hand.R` 上的
   756 个顶点。本轮把它分离成独立网格并改绑 `weapon.R`（权重 1.0），**新增几何 0**，
   逐帧验证 attack/death 不脱手（偏差 7e-7）、不穿地（最低点 ≥ +0.002）。
2. **战斗**：新增可操作场景 `godot/battle/hero_battle_stage.tscn`，输入为
   **A/D 或 ←/→ 左右移动、J 或 空格 攻击、R 重开**（只有左右两个方向，没有 W/S，此前写「WASD」是虚报，已改）
   驱动移动、攻击命中扣血、受击、死亡、胜负、重开，五动作由状态机真实驱动；
   19 项断言全过，附胜利/失败两段引擎内录屏。

## 二、为什么不是「直接加个武器」

用户要求「先检查现有可见武器 mesh 实际绑定，勿重复添武器」。检查结果：

- 场景只有 `hero005_rig` + `hero005_costume_and_body`（14409 顶点）+ 一个 42 顶点遗留 Icosphere
- 顶点组 10 个，**没有 weapon.R**；`hand.R` 覆盖 1358 顶点（手 + 武器）
- 连通分量分析：756 个顶点（60 个分量）100% 由 `hand.R` 驱动，到该骨距离 0.26–1.66；
  手部本身距离只有 0.011–0.105 → 以 0.25 为界可干净分开

所以做法是**搬现有几何**，不是新建武器。

## 三、逐帧验证抓出的两个真问题

| 问题 | 首轮实测 | 原因 | 修法 | 修后 |
|---|---|---|---|---|
| attack 武器穿地 | −0.0235 | 静止姿态枪尾就在地面下 2cm（模型固有） | 武器顶点沿世界 Z +0.026 | **+0.0025** |
| death 身体+武器穿地 | 身体 −0.0705 / 武器 −0.1473 | 倒地绕脚底旋转，中段躯干扫过地面（此前只验末帧） | root 逐帧贴地补偿（9 帧） | **+0.0020** |

**为什么不用旋转**：武器最低点几乎在 `weapon.R` 骨 head 正下方，绕该点旋转只按 `1−cosθ`
变化（实测 15° 只抬 0.0016）。**为什么不能平移 rest 骨**：蒙皮是 `M_pose × M_rest⁻¹`，
rest 与 pose 同步平移后仍是单位阵，顶点不动（实测 minZ 完全没变）。

## 五、测试与证据

```
bash tools/godot-battle-test.sh
→ 19/19 PASS（移动/攻击 452ms 判定/受击/击杀/胜利/重开/失败/HUD 同步/再重开）
→ 报告 docs/evidence/CMD-010/battle-flow-report.json
```

| 证据 | 说明 |
|---|---|
| `battle-win.mp4` | 胜利局，1280×720/30fps/24s，**Godot 引擎内录屏**（`--write-movie`） |
| `battle-lose.mp4` | 失败局，14s 截取，同上 |
| `win-1..4*.png` | 待机 / 移动 / 交战 / 胜利+敌人倒地（武器仍在手） |
| `lose-defeat.png` | 失败瞬间自动截图（HP 0、玩家倒地、武器在手） |

**录屏性质**：`--write-movie` 由引擎渲染管线逐帧写出 AVI/MJPEG 再转 H.264，
**不是操作系统实屏录制**，不依赖屏幕录制权限。

## 六、过程中修掉的自身 bug

1. **HUD 在胜负判定后不再刷新**：`_process` 里 `battle_over` 直接 return，`_update_hud`
   被跳过，导致画面停在 HP 4 而实际已 0。修法：`_finish()` 主动刷新，并补两条 HUD 断言。
2. **R 键按住每帧重开**：缺边沿检测，加了 `_r_held` 锁存。
3. **失败演示没跑起来**：`--demo-lose` 时 `_demo` 仍为 false，演示驱动未被调用。

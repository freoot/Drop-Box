## 一、跨进程保存/加载验收（新增）

### 1.1 为什么必须新写一个脚本

主测试里的 A6 是这么写的：

```gdscript
stage.queue_free()          # 同进程里销毁场景
stage = _spawn()            # 同进程里重新实例化
```

它证明的是「**同一进程内**存档路径稳定 + 场景能回读自己的存档」，
**不等于**「关掉游戏再打开还能读回来」。所以单靠 A6 不敢宣称存档闭环。

### 1.2 现在的验收（`tools/godot-save-cross-process-test.sh`）

沿用既有隔离框架（**不重建路径体系**）：独立临时项目副本 + 副本内 `override.cfg`
指定独立 user 目录 → 正式档 `user://save.json` 落在隔离目录里，
主项目与真实用户目录全程只读 sha256 校验。

新增场景参数 `--auto-flow`：**使用正式存档模式**（不切专属新档）自动跑完
「打虎 → 招募 → 编队」，然后**正常退出（退出码 0）**；
超时没跑完则退出码 **2**，不假装成功。

| 步骤 | 进程 | 期望 |
|---|---|---|
| 进程 1 | 独立 Godot 进程 A | 退出码 0、`[FLOW] DONE`、首次招募到武松 |
| 进程 2 | 独立 Godot 进程 B | 退出码 0、`[RECRUIT] 武松已在队伍中，不重复发放` |
| 落盘校验 | 同一份 `save.json` | `owned` 里 wusong **恰好 1 个**、`lineup` 恰好 1 个 |
| 收尾校验 | 主项目 + 真实用户目录 | 逐字节 sha256 **完全一致** |

**实测输出**（`docs/evidence/CMD-015/cross-process-report.txt`）：

```
进程1 PID=8260 退出码=0     进程2 PID=8361 退出码=0
owned wusong 计数：进程1后=1，进程2后=1
lineup wusong 计数：进程1后=1，进程2后=1
```

两个 PID 不同 → 确实是两个进程，不是在同一进程里自我复读。

## 二、如实修正：中断清理与子进程跟踪

### 2.1 之前的问题

`tools/godot-tiger-test.sh` 原来写着：

```bash
cleanup() {
  if [ -n "${CHILD_PIDS:-}" ]; then   # ← CHILD_PIDS 从来没被赋过值
    for pid in ${CHILD_PIDS}; do ...
```

Godot 当时是**前台**跑的（`| tee`），PID 根本没被记录，
所以这段清理**永远不会执行**——是纸面能力，不是真能力。

### 2.2 现在的行为

- Godot 改为**后台启动并记录真实 PID** 到 `CHILD_PIDS`（`track_child` / `untrack_child`）
- `trap cleanup EXIT` 负责收尾；新增 `on_signal` 处理 INT/TERM
- 清理顺序恒定：**kill 子进程 → wait 等它真正退出 → 再删本次临时目录**

**实测中断**（给脚本发 SIGTERM）：

```
脚本退出码：130
残留临时项目副本数：0
残留 Godot 测试进程数：0
```

> `~/Library/Application Support/` 下还剩 2 个 `shuihu_tiger_test_*` 目录，
> 时间戳是 **15:48 / 15:58**，属于更早几轮运行的遗留，**不是本轮产生的**。
> 本轮中断后自己建的目录已被清掉。清理历史遗留需要另行确认后再动。

### 2.3 顺带修掉的自相矛盾

`tools/verify-save-safety.sh` 场景 E 原本**直接在主项目写一份 `override.cfg` 再删掉**，
与脚本头部「本脚本不在主项目里写任何配置文件」的说法冲突。
已改为在**第二个隔离副本**里预置配置，校验「预置配置未被覆盖且仍然生效」，
主项目全程零写入。8/8 场景仍全过。

## 三、试玩可读性（r2）

### 3.1 改动前后对照

| 项 | 之前 | 现在 |
|---|---|---|
| 状态区 | 裸文字浮在画面左上，无底色 | 半透明深底 + 金边面板，四行信息分组 |
| 血量/怒气字号 | 17 px | **23 px** |
| 阶段标题字号 | 26 px | **30 px** |
| 按钮字号 / 尺寸 | 18 px / 180×44 | **22 px / 350×80** |
| 文字对比度 | 无描边 | **黑色描边 ≥5 px**（`outline_size`） |
| 血量/怒气条 | 默认细条 | 圆角 + 描边 + 分色（血红 / 怒金） |
| 目标 | **点击无任何反馈**（源码里是 `pass`） | 脚下**金圈** + 头顶**金箭头**（浮动）+ HUD 常驻「目标：吊睛白额大虫（已锁定）」；点虎重新锁定，点空处给一句话提示 |
| 大招可不可放 | 只有按钮禁用态 | 怒气 ≥50 → 顶部金色横幅「★ 虎影重击就绪」+ 怒气行变金 + 按钮文案切「-50 怒气」 |
| 文案 | `武松 HP 120/120`、`回合：我方`、`【教学】` | `武松 生命 120 / 120`、`你的回合`、无方括号标签 |

### 3.2 顺手修掉的一个真 bug

按钮文案原先在 `_set_buttons_enabled()` 里写死，**不随怒气实时刷新**：
怒气已经 50 了，按钮上仍显示「还差 25」。现在文案统一由 `_update_hud()`（每帧刷新）驱动，
并把「还差 N」挪到 HUD 怒气行，按钮只保留「-50 怒气 / 需 50 怒气」两种短文案
（原先长文案在 350 px 按钮里会溢出屏幕右缘）。

### 3.3 为什么不设「必须先点中才能攻击」的硬门槛

场上只有一只虎，战斗开始即自动锁定并高亮；点击可重新锁定。
不做硬门槛是为了避免玩家误点后**无法出手**（死锁），
同时「打的是谁」已经通过金圈 + 箭头 + HUD 三重提示做到一眼可见。

### 3.4 点击判定放在 `_unhandled_input`

最初用 `_input` 接鼠标，结果**点界面按钮也会走射线检测**——
按「出拳」时右上角会弹一句「没点中猛虎」的假提示。
改用 `_unhandled_input`（被 GUI 先消费的点击不会到达这里），假提示消失。
A15h 同步改为调用 `_unhandled_input`。

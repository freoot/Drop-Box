# ACT-003 · 首批角色动作规格

> 适用范围：ART-002 r7 b1 已交付的 18 个 GLB 角色中的首批 5 人。
> 时间基准：**24 fps**（`assets/releases/ART-002/r7/batches/b1.json.fps = 24`，与 r5/r6 manifest 一致），1 帧 = 41.67 ms。
> 长度单位：**Blender 世界单位**（`body_height = 2.145`，`grid.spacing = 1.2`，`ground_y = 0.06`，均来自 r6/r7 manifest 实测字段）。
> 本文所有数值为**建议区间或具体帧数**，不是结论性断言；落地前需与 A 侧对 GLB 内部轨道做一次复核（见 §6 遗留项）。

## 1. 通用节拍框架

### 1.1 三类攻击包络

按武器重量与握持方式分为三档，各档的**命中时点**与**总时长**不同。

| 类型 | 适用武器 | 攻击总长 | 前摇（起手→出手） | 命中帧 / ms | 命中保持 | 收招 |
| --- | --- | --- | --- | --- | --- | --- |
| **A 标准单兵** | `spear`、`sword`、`saber`、`broadsword`、`staff` | 24 帧 / 1000 ms | 帧 0–8（0–333 ms） | **帧 11 / 458 ms** | 帧 11–13（458–542 ms） | 帧 13–24（542–1000 ms） |
| **B 重型长柄** | `guandao`、`monkstaff`、`battle_axe`、`wolf_mace` | 28 帧 / 1167 ms | 帧 0–10（0–417 ms） | **帧 13 / 542 ms** | 帧 13–16（542–667 ms） | 帧 16–28（667–1167 ms） |
| **C 双持两段** | `monkblade`、`double_axe`、`double_spear`、`double_whip` | 40 帧 / 1667 ms | 段1 帧 0–9（0–375 ms）<br>段2 帧 20–29（833–1208 ms） | **段1 帧 9 / 375 ms**<br>段2 帧 29 / 1208 ms | 帧 9–13（375–542 ms）<br>帧 29–33（1208–1375 ms） | 帧 13–20（542–833 ms）<br>帧 33–40（1375–1667 ms） |

- A 类命中帧 11 直接沿用现有时点：`CONTACT = 11/24`（`combat-motion-timing.js`）与 `impactFrame: 11`（`assets/models/cutout/motion-manifest.json`）一致。
- C 类**伤害只在段1 命中帧（375 ms）结算一次**，段2 为表现性挥击。依据：`combat-motion-timing.js` 首行注释「damage happens once at CONTACT」，现有模型不支持单次攻击两次结算。

### 1.2 其余四动作的统一时长

| 动作 | 建议时长 | 依据 |
| --- | --- | --- |
| 待机 idle | 48 帧 / 2000 ms，循环 | 沿用 `b1.json.clips.idle`（帧 0–48 / 2.0 s） |
| 移动 walk | 24 帧 / 1000 ms，循环，每周期 2 步 | 沿用 `b1.json.clips.walk`（帧 0–24 / 1.0 s） |
| 受击 hit | 18 帧 / 750 ms，不循环 | 沿用 `b1.json.clips.hit`（帧 0–18 / 0.75 s） |
| 死亡 death | **30 帧 / 1250 ms，不循环** | **现有任何脚本与清单中均无 death，属新增** |

### 1.3 已发现的两处时点冲突（需 A 侧拍板）

| # | 冲突内容 | 建议处理 |
| --- | --- | --- |
| 1 | 战士近战命中：`battle-motion.js.contactMs` 给出 **294 ms**，`combat-motion-timing.js.CONTACT` 换算为 **458 ms** | 建议统一到 **458 ms（帧 11）**：它与 `impactFrame: 11` 同源，且 `attackPose` 的前摇/收招分段都是围绕它设计的。若保留 294 ms，则 A 类前摇需压缩到 帧 0–7（0–292 ms），收招相应延长 |
| 2 | `attackPose` 收招段用 `(t - .56) / .55` 归零，需到 `t = 1.11`（**1110 ms**）才结束，但攻击片段只有 1000 ms | 建议把收招窗口改为 **帧 13–24（1000 ms 内归零）**，或把攻击片段延长到 27 帧（1125 ms）。两者取其一，不要同时保留 |

### 1.4 位移量的换算依据

现有 `attackPose` 的 `step` 是**演示画布像素**（`combat-motion-studio.js:22` 中 `x += pose.step`，角色绘制尺寸 500×500）。换算到世界单位：

```
500 px（绘制高） ÷ 2.145 单位（body_height） ≈ 233 px / 单位
蓄力后撤 −22 px → −0.094 单位
前冲峰值 +42 px → +0.180 单位
总行程    64 px →  0.275 单位
棋格间距  1.2 单位（r6 manifest grid.spacing）→ 前冲峰值 ≈ 0.15 格
```

`lean` 为弧度：`−0.045`（蓄力后仰）→ `+0.06`（命中前倾）。

**林冲专属约束**
1. r6 复用：`reuse_exact: true`，**不得改写 `../r6/models/linchong.glb` 与 `../r6/source/linchong.blend`**。新增 `death` 片段需在 r7 下新建分支文件，或在网页表现层用 CSS/JS 合成。
2. `sampled_contacts` 全部为遗留 0.0（`sampled_contacts_limitation`），**不能作为脚底验收依据**，需重新采样。
3. `assets/rigs/linchong-layers/manifest.json` 中所有部件 `hiddenJointPaint: "missing"`，分件旋转会在关节处出现断口，动作幅度越大越明显。首批建议限制 `arm.R` / `leg.*` 的极限旋转在已登记限位内（如 `forearm_near` −10°~115°、`upper_arm_near` −65°~70°）。
4. 披风 `cape` 是 rigs 中登记的部件，建议滞后躯干 2–3 帧跟随，避免与 `leg.L/R` 交叉穿模。

| **攻击** | 40 帧 / 1667 ms（两段） | **段1** 前摇 0–375 ms（帧 0–9）双斧举过头顶<br>**命中1 375 ms（帧 9）** ← 唯一结算点<br>保持 375–542 ms（帧 9–13）<br>收招 542–833 ms（帧 13–20）<br>**段2** 换向 833 ms（帧 20）横抡<br>前摇 833–1208 ms（帧 20–29）<br>**命中2 1208 ms（帧 29）**（表现，不结算）<br>收招 1375–1667 ms（帧 33–40） | 段1 前冲 +0.30–0.38 单位（冲锋感最强）；段2 横向摆动 0.25–0.35 单位；净位移 0 | 斧刃在帧 9 到达最低点，与地面间隙 ≥ 0.05 单位；两斧轨迹不得交叉 |

**李逵专属约束**
1. 段1 前冲 0.30–0.38 单位是五人中最大的，需确认不会越过目标格边界：目标在相邻格（1.2 单位），前冲 0.38 单位约为 0.32 格，仍在安全范围内；若战棋格距不是 1.2 单位需重算。
2. 双斧举过头顶时，`arm.L` / `arm.R` 同时上举，两把斧在头顶上方可能相交：建议两手的横向偏移 ≥ 0.12 单位。

## 7. 防穿模与防滑步约束（五人通用）

### 7.1 脚底对齐

| 约束 | 建议值 | 依据 |
| --- | --- | --- |
| 鞋底最低点 `sole_min_z` 目标值 | `ground_y = 0.06` 单位（r6 manifest `grid.ground_y`） | GLB 内 `body_bounds.sole_bottom_z = 0.0`，与 `ground_y` 存在 0.06 的基准差，需明确采用哪个基准 |
| 允许偏差 | `|sole_min_z − ground_y| ≤ 0.02` 单位 | 约等于身高的 0.9%，在 Q 版比例下肉眼不易察觉 |
| `root_correction` | 每帧记录，用于把偏差补回根节点 | 现有字段已存在，但 r6 遗留值全为 0.0，**不可直接引用** |
| 待机 / 受击期间的脚底 | 双脚均需满足上述偏差；不得出现单脚悬空却无抬腿动作 | — |

### 7.2 根节点位移与步频匹配（防滑步）

- 防滑步的基本条件：**支撑脚在世界坐标中静止**。若一个支撑相内根节点前进了 `D` 单位，则脚相对根的位移必须是 `−D`。
- `tavern-gait.js` 的 `foot(phase)` 已实现这一关系：支撑相（`p < 0.6`）内脚沿 x 从 `+18` 匀速到 `−18`（共 36 px），摆动相抬起 `18·sin(πt)`。战棋侧需保证根节点每步前进量等于该段行程。
- 建议参数：`walk` 每周期 1000 ms、2 步 → 步频 2 步/秒；根节点速度 2.0–2.6 单位/秒 → **步幅 1.0–1.3 单位**。
- 若单格实际耗时不是 460–560 ms，则步频与格距不匹配，会出现滑步。此时应调整**根节点速度**而不是调整步频。
- 攻击中的前踏：`step` 峰值对应的世界位移见 §1.4（0.18 单位）。前踏期间支撑脚必须保持贴地，不得随根一起前移。

### 7.3 武器与身体的层级关系

| 约束 | 建议值 |
| --- | --- |
| 武器挂点 | 单持 → `hand.R`；双持 → `hand.L` + `hand.R`；长柄双手 → 主挂 `hand.R`，`arm.L` 协同。**GLB 内实际挂点未确认，需 A 侧复核** |
| 武器与躯干最小间距 | ≥ 0.03 单位（任何帧） |
| 长兵末端与地面最小间隙 | ≥ 0.05 单位（任何帧，含攻击最低点与死亡倒地） |
| 双持武器之间最小间距 | ≥ 0.12 单位（避免头顶举械时相交） |
| 披风 / 衣摆（`cape` 等） | 滞后躯干 2–3 帧跟随；不作为碰撞体；与 `leg.*` 交叉时不阻断 |
| 分件旋转限位 | 已登记部件的动作幅度应在 `linchong-production-plan.json` 的 `rotationDegrees` 范围内（如 `upper_arm_near` −65°~70°、`forearm_near` −10°~115°、`pelvis` −12°~12°、`torso` −18°~18°、`head` −15°~15°）。超出范围处因 `hiddenJointPaint: "missing"` 会露断口 |

### 7.4 受击位移上限

| 项 | 建议上限 |
| --- | --- |
| 水平后退位移 | **0.18 单位（0.15 格）**，实测各角色取值 0.05–0.15 单位 |
| 后退后是否回位 | 建议回位到原格中心，回位不额外占用时间（在 750 ms 内完成） |
| 后仰旋转 | 0.16–0.26 rad，按体型/兵器重量递减（轻装短兵 0.26，重兵器 0.16） |
| 顿帧 | `HIT_STOP = 75 ms`（`combat-motion-timing.js`），受击动画从顿帧结束后开始计时 |
| 死亡水平滑动 | ≤ 0.12 单位，**不得跨格** |

### 7.5 死亡动作通用约束（新增，现无参考）

- 时长统一 30 帧 / 1250 ms，末帧冻结（不循环）。
- 触地统一在 **帧 16（667 ms）**，之后 583 ms 为静止保持 —— 这段留给 UI 显示"阵亡"标记与摄像机停留。
- 根节点最终高度 **0.45–0.65 单位**（约为身高的 21%–30%），不建议完全躺平（Q 版比例下躺平会丢失剪影识别度）。
- 死亡期间**不触发** `receiving-hit`（`battle-motion.js` 的受击类），需新增一个 `performing-death` 类或等效状态，避免与受击动画互斥。

## 8. 复用策略

### 8.1 可复用的前提

18 个 GLB 的 `body_height` 全部为 2.145（共享构造），骨骼名集合完全一致（`root, body, head, arm.L, hand.L, arm.R, hand.R, leg.L, foot.L, leg.R, foot.R`），且全部 `role: warrior`。因此**同体型角色的骨骼动画可跨角色套用**，只需替换模型。

### 8.2 逐动作复用判定

| 动作 | 复用结论 | 说明 |
| --- | --- | --- |
| **待机 idle** | **分 3 套复用** | ① 长兵组（`spear` 2 人 / `guandao` 1 / `monkstaff` 1 / `pudao` 3 / `broadsword` 1 / `staff` 2）：持械斜立，共 10 人<br>② 短兵组（`sword`/`saber`/`battle_axe`/`wolf_mace`）：4 人<br>③ 双持组：`monkblade` 武松、`double_axe` 李逵、`double_spear` 董平、`double_whip` 呼延灼，共 4 人 |
| **移动 walk** | **1 套复用**（18 人） | 同体型同骨骼，步幅一致。需单独检查：林冲的 `cape` 披风、鲁智深/李逵的体型感（建议只加 0.01–0.03 单位的重心下沉，不改步频） |
| **攻击 attack** | **不能跨武器复用，按武器组复用** | 见 §8.3 |
| **受击 hit** | **1 套复用**（18 人） | 只按体型微调后仰峰值（0.16–0.26 rad）与后退量（0.05–0.15 单位），不出新片段 |
| **死亡 death** | **1 套复用**（18 人） | 全新增一套即可，倒地姿态按体型的差异控制在根节点高度区间内 |

### 8.3 攻击动作的分组复用

| 组 | 成员 | 包络 | 能否共用一套动画 |

### 8.4 必须单独制作的部分

1. **所有 `death` 片段**：现有资产中完全不存在，需新建；但因可跨角色复用，实际只需出 1 套。
2. **r6 复用角色（林冲 / 鲁智深 / 武松）的任何修改**：`reuse_exact: true` + `reuse_sha_match`，**不得改写 r6 源**。需要新动作时在 r7 下新建分支文件，或在网页表现层用 CSS/JS 合成（后者不需改模型）。
3. **B 类与 C 类的片段长度**：超过现有 `attack` 的 24 帧包络，需新增片段定义（或按 §3、§5 的折中方案拆分播放）。
4. **武器挂点**：GLB 内部实际挂点未确认（§7.3），若不是 `hand.R` / `hand.L`，所有攻击动画的手部轨迹都要重做。

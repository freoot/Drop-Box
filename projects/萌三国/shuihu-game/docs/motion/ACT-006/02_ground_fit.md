# ACT-006 · death 贴地求解，以及对 ACT-005 结论的补正

## 1. ACT-005 哪里错了

ACT-005 交付 hero005 的 r8 时，death 用固定下沉 `0.1`，验收里写了「末帧倒地贴地」，
但**当时没有量任何高度**，判据是「截图里能看到人躺下」。

ACT-006 用蒙皮网格包围盒实测同一个文件（`docs/evidence/CMD-007/motion/11-death-end-1583ms.png` 对应的那一版）：

```
hero005 r8 death 末帧：minZ = -0.5802   maxZ = 0.3501
```

模型站立高度约 2.1–2.6 单位，也就是**半个身子在地面以下**。回看那张截图确实能看出来：
躯干被地面切掉，只剩上背和头露在外面；当时被当成「贴地」放过了。

**这是验收标准的错，不是渲染的错**：只写「看起来躺下了」，没写「最低点离地多少」，
就等于没判据。本文件把判据补成可量化的两条：

| 判据 | 阈值 | 现在的结果 |
|---|---|---|
| death 末帧蒙皮网格世界最低点 \|minZ\| | ≤ 0.05 | 18/18 都是 **0.0003** |
| death 末帧最高点 ÷ 站立高 | < 0.7（确实躺下） | 0.32 – 0.43 |

## 2. 为什么固定值不可能对

`root` 骨在**脚底**，`death` 的动作是「绕脚底前倾 78°」。
绕脚底转，身体中段会向地面以下扫过去，重心越低、身高越高，扫得越深。

用同一套关键帧、只改 sink 采样两次，得到的关系是**严格线性**（斜率 −1.0000，
说明 root 局部 Y 轴与世界 Z 轴平行，位移 1:1 传递到世界坐标）：

| sink | 末帧 minZ |
|---|---|
| 0.00 | −0.4808 |
| 0.20 | −0.6808 |

所以要让 minZ = 0，需要的是 **−0.4808（上抬）**，而不是 ACT-005 用的 +0.1（下沉）。
两个方向都反了：ACT-005 在已经埋 0.48 的基础上又往下压了 0.1，于是变成 −0.58。

## 3. 求解算法（`tools/motion/build_r8_death.py::fit_sink`）

```
1. build_death_action(sink=0.0)   → 量 minZ0
2. build_death_action(sink=0.2)   → 量 minZ1
3. slope = (minZ1 - minZ0) / 0.2
4. sink  = clamp(-minZ0 / slope, -0.9, 0.9)
5. build_death_action(sink)
6. 实测 minZ；若 |minZ| > 0.02 且 slope 有效 → sink -= minZ / slope，重建一次
7. 把 sink / minZ / maxZ 写进 build_log_<hero>.json
```

- 测量函数只统计「带 Armature 修改器且指向本骨架」的 mesh（见 01 文档第 6 节的 Icosphere）。
- `sink` 允许为负（上抬）是关键：第一版把它钳在 `[0, 0.8]`，解被截断成 0，
  18 个角色全都会埋在地里。
- 每个角色的 sink 与实测 minZ 都留在 `assets/releases/ART-002/r8/models/build_log_<hero>.json` 里，可逐个复核。

## 1. 改了哪些函数

### 1.1 `game.js`

| 位置 | 改动 | 作用 |
|---|---|---|
| `QUALITY` 之后 | 新增常量 `GACHA` | 概率、保底阈值、重复补偿的**单一口径来源**；文案与逻辑同源，避免公示与实际脱节（CMD-002 F#1） |
| `initialState()` | 新增 `jadePity:{pulls:0,eliteMiss:0}`、`lastRecruitMode:''` | 跨轮保底计数与「再来一次」所需的上次池子记忆 |
| 读取存档后 | `state.jadePity=Object.assign({...},state.jadePity||{})` 等三行 | 旧存档缺字段时补默认值，避免 `undefined` 参与计数 |
| `pullQuality(mode)` | 重写 | ① 跨轮硬保底：`pulls>=10` 直接返回暗金；② 名士软保底：第 8 次起每多一次，暗金权重 +3 个百分点（上限 60%）；③ 基础权重改读 `GACHA` |
| `recruit(mode)` | 重写循环体 | 每次抽取后更新计数：出暗金归零，未出则 +1（名士另计 `eliteMiss`）；记录 `lastRecruitMode`；十连末位保底逻辑保留 |
| `obtainHero(id)` | 重复分支扩展 | 返回 `shardsGained` / `jadeGained`；暗金重复额外回玉璧 |
| 新增 `dexSummary()` / `dexLine()` | 收集进度 | 输出 `已入寨 n/108` + 四档小计，招贤面板与将册共用同一出口 |
| 新增 `pityLeft()` / `pityLine()` | 保底读数 | 输出「距保底约 N 次」，名士另附已连续未出暗金次数 |
| 新增 `shardProgressLine()` | 信物进度 | 显示当前定向目标 `信物 x/30` |
| `recruitOptions()` | 插入进度与保底、改写尾部说明 | 未挂载 `SHUIHU_TAVERN_UI` 时的降级路径同样可见 |
| `heroPage()` | 标题下插入 `${dexLine()}` | 将册页可见总量与分档 |
| `clickAction()` | 新增 `reveal-hero` / `reveal-again` | 抽后去向的两个动作 |
| `finishBattle()` | 主线首胜 +20 玉璧；试练塔每 5 层 +15 玉璧 | 玉璧产出闭环 |
| `daily-task` 处理器 | +25 玉璧 | 稳定日常产出 |

### 1.2 `tavern-ui.js`

| 方法 | 改动 |
|---|---|
| `options()` | 标题下插入 `${dexLine()}${pityLine()}`；规则折叠区改为 `${this.ruleText()}` |
| 新增 `ruleText()` | 概率与保底文案**由 `GACHA` 常量生成**，并写明玉璧三个来源、本地存档口径 |
| 新增 `revealActions()` | 抽后三按钮：`查看 X` / `再来 N 次` / `收下这份缘分`，末尾附保底读数 |
| `reveal()` | 卡面状态文案改用 `shardsGained`/`jadeGained`；插入 `${this.revealActions()}`；十连时不再渲染独立的 `summon-confirm` |

新增 `.dex-progress`、`.pity-row`、`.pity-chip`、`.shard-chip`、`.summon-actions`、`.summon-next`、`.summon-again`、`.summon-take` 等样式；并为十连/单抽结果页做了高度收敛与动作栏常驻处理（见第 4 节）。

## 2. 取值与规格对照

| 项 | CMD-002 建议区间 | 本步取值 | 说明 |
|---|---|---|---|
| 把酒相邀权重 | 蓝 48–56 / 紫 30–37 / 红 10–15 | 蓝 53 / 紫 34 / 红 13 | 与现状一致，落在区间内，未改动 |
| 名士来访权重 | 红 78–85 / 暗金 15–22 | 红 83 / 暗金 17 | 保持现状，另加软保底 |
| 跨轮硬保底 | 8–12 次量级 | **10 次** | 取区间中值，与十连长度对齐，便于解释 |
| 名士软保底起点 | 8–12 次 | **8 次** | 取区间下沿，让名士池更早有反馈 |
| 软保底步长 | — | **+3 个百分点／次**，上限 60% | 上限避免名士池变成暗金池 |
| 每日玉璧 | 20–30 | **25** | 中值 |
| 主线首胜玉璧 | 15–25 | **20** | 中值，六章合计 120 |
| 试练塔玉璧 | 每 5 层 10–20 | **每 5 层 15** | 中值 |
| 重复暗金补偿 | 信物 8–12 枚 | **信物 10 枚 + 玉璧 15** | 取中值，另加回玉以强化「不亏」感知 |
| 重复红将 | — | 信物 7 枚 | 居于暗金（10）与紫蓝（5）之间 |
| 重复紫/蓝 | 5 枚 | 5 枚 | 维持现状 |
| 十连末位保底 | 保留 | 保留 | 第 10 位仍强制暗金 |

**玉璧节奏测算**（初始 260）：首周按「每日 25 × 7 + 六章首胜 20 × 6 + 试练塔三个五层 15 × 3 ≈ 340」累计约 600，可支撑约 3 次十连，不会出现「只能抽一次」的死锁。

## 4. 本地验证

### 4.1 打开方式

```bash
cd /Users/user/Documents/Codex/youxi/meng
```

### 4.2 点击路径（手工）

1. 首次进入填名字 → 底栏「招贤」→ 点酒肆里的掌柜（或「掌柜 · 招贤」牌子）打开招贤弹层。
2. 弹层标题下应看到：`已入寨 5/108` + 四档小计，以及 `距保底约 10 次`。
3. 点底部折叠条「寻访规则与概率」，确认概率文案与实现一致、含玉璧三个来源。
4. 玉璧归零后点「群英赴宴」→ 应提示「玉璧不足」且不扣成负数。
5. 去「玩法」→「领取」每日聚义赏 → 玉璧 +25。
6. 打一场主线首胜 → 结算文案含「首胜玉璧 +20」；同一关再打一次不再给。
7. 玉璧够 200 后点「群英赴宴」→ 结果页 10 张卡；底部常驻栏「查看 X」/「再来十次」/「收下这份缘分」。
8. 点「查看 X」→ 跳到将册并选中该将，顶部仍显示 `已入寨 n/108`。
9. 抽到已拥有的暗金 → 文案显示「信物 +10 · 玉璧 +15」。

## 四、写规格过程中发现的、与任务单假设不一致的事实（供指挥官判断）

以下四条为只读核对时发现的现状偏差，已在规格正文中按事实修正，并作为设计输入：

1. **玉璧在代码中只减不增。** `game.js` 仅有两处 `state.jade-=`（30 与 200），初始 260，无任何增加点。任务单假设「现有招贤资源消耗」可对照，但现状是十连只能进行 1 次。规格 B.3/B.4 已把「补玉璧产出」列为 P0 前置。
2. **十连保底不是累计计数，而是末位判定。** `recruit('ten')` 内 `i===count-1&&!hasDark`，跨轮不累计。规格 B.3 因此建议补「跨轮累计」而非改写现有末位逻辑。
3. **可直接抽取的暗金只有 4 位。** 暗金池 14 人，开局赠 5 人、剧情首胜发 5 人、朱武为紫；`pullCandidate()` 优先未拥有，故两次十连后保底位退化为重复。这是「保底价值断崖」的结构原因，规格 B.2 已单列。
4. **「图鉴」在现有代码里仅指合击图鉴。** `图鉴` 二字出现在 `comboBook()`（梁山合击图鉴）与羁绊提示处，将册本身只有 `owned`/`unowned` 样式区分，无 `n/108` 总量进度。规格 D.3 的进度条因此属新增项，不属改造项。

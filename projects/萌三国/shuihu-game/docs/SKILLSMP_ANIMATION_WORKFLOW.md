## 筛选
采用：
1. affaan-m/ECC 的 blender-motion-state-inspection：识别脚底滑动、坐标朝向、骨骼/网格偏差，要求先读结构再看渲染。
2. calesthio/OpenMontage 的 character-rigging：独立部件、明确父子关节、旋转限制、层级、视图及可复用数据包。
未采用：付费云端生成、通用网页/银河粒子、无关角色人格技能。仓库星数不是技能质量证明。

## 当前项目判断（源码依据，不是运行验收）
- linchong_combat_motion.py 使用图像网格形态键，没有独立髋膝踝骨链。不能把它描述为完整骨骼跑步。
- 前进距离在演示脚本中单独计算，未与每步步长绑定；存在足底滑动风险。
- 跑步使用休闲服，攻击使用战斗服，切换不一致。
- 枪与人物在同一张图上，缺少独立持枪点和双手握持约束。
- 强化停顿、位移和闪光只能改善节奏，不能补出原画没有的关节姿态。

## 已落地的制作约束
assets/rigs/linchong-production-plan.json 包含18个部件/控制节点、父子关系、独立层级、旋转范围、跑步接触事件、出枪时序及制作完成条件。关节坐标是草案，素材字段保持null，不冒充已完成分层。它不替换现有角色，也不是已绑定的动画。

后续制作顺序：同服装战斗原画 → 独立上下臂/手/髋/大小腿/脚/武器 → 隐藏关节补画 → 根位移与支撑脚约束 → 出枪握持/接触点 → 受击 → 特效。未补好分层素材前不继续放大全图变形。

遵守用户本轮既有约束：本地 Blender，不调用付费图像生成；未运行游戏/动作验证。新增测试留下一轮执行。

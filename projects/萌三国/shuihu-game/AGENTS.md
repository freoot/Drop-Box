# 水浒游戏多人 AI 协作协议

适用范围：本目录及子目录。遵守上层 AGENTS.md 和用户最新指令。
本文件为共享项目协议，名称为 AGENTS.md，不是 Agent S.md。

## 目标与验收责任

制作原创 Q 版水浒浏览器战棋游戏。以现有网页原型为基线，不自行迁移引擎。
用户是产品决策人；Codex 只负责要求、审美评审与最终独立验收。A（当前主实现代理）负责全部实现、调度和集成，D 负责独立试玩 QA。
唯一工程基线为本目录，游戏入口为 index.html，动作页为 combat-motion-studio.html；直接复用本目录成果，不复制覆盖工程。login-page/ 仅保留历史文件，不作为游戏交付，不接入新登录，不改成其他游戏。
未经用户另行指示，Codex 提交缺陷与验收结论，功能修复由对应负责人实施。
测试通过不等于画面合格，不得将静态代码检查称作浏览器试玩。

## 角色分工与文件所有权

### A：工程、资料整理与调度负责人

- 负责功能、存档、战斗规则、数值、资源加载、依赖、资料索引、任务派发与合并。
- 独占编辑：game.js、hero-power.js、journey.js、data/shuihu.js、manifest.json、tools/、godot/、project.godot。
- 集成专管：index.html、README.md、GAME_DESIGN.md、AGENTS.md。B/C 提交修改请求，不能并发编辑。
- 为每个任务分配唯一 ID、基线提交、负责人、允许文件、验收条件和依赖。
- 将需要同时改画面和逻辑的任务拆为接口约定、C 实现、A 接入三个阶段。
- 使用 Git 提交获取工作成果，不通过覆盖整个项目文件夹集成。

### B：音乐与音效负责人（2026-10-23 起）

- 制作三首轻松明亮国风日常、两首积极有力战斗候选，每段 30–45 秒、可循环、统一试听音量；用户选定前不替换默认曲，禁止阴沉压抑、刺耳音色。
- 优先本机软件与已有合法音源，不购买、不使用收费生成；记录来源、可编辑制作源和导出参数，旧素材只读。
- 挥击、打击、箭矢、法术、护盾、受击音效按真实动作/命中帧触发；音乐和音效分别开关，限制并发与峰值，展示层不结算战斗。
- 独占编辑：audio-candidates.html/js/css、audio-sfx.js、assets/releases/AUDIO-002/、tests/audio-002.test.mjs、docs/collaboration/handoffs/AUDIO-002.md。bgm.js、game.js、index.html 接入由 A 串行集成。
- 原叙事内容成果保留，data/hero-stories.js、data/journey.js、docs/content/ 本轮只读；水浒故事与绰号在姓名前的规则继续有效。
- 不修改角色 ID、排名、数值、技能效果、关卡 ID、既有数据字段或全局变量名。
- 小说演义与历史分开；原创改编标明改编。姓名采用“绰号 · 姓名”；武松打虎地点是景阳冈。
- 技能说明必须与结算吻合；发现矛盾报给 A，不能凭文案创造尚未实现的效果。
- 联网资料保存 URL、标题、访问日期及引用依据；不得照搬其他游戏文案。

### C：界面、角色表现与可视化负责人

- 负责主城构图、建筑入口、字体、移动适配、角色比例、待机/攻击/受击动作和特效。
- 独占编辑：game.css、battle-readability.css、battle-vfx.css、battle-vfx.js、battle-motion.js、character-studio.*、combat-motion-studio.*、combat-motion-timing.js、tavern-*.js、tavern-motion.css、data/portraits.js。
- 新素材仅新增到 assets/releases/<任务ID>/；原素材只读。保留可编辑源文件、导出参数与版权来源。
- 需要 game.js/index.html 接口时向 A 提交明确的函数、事件、类名和数据协议，不抢改 A 文件。
- 展示层不得扣资源、算伤害或保存战斗结果；特效只读取真实结算和状态。
- 治疗、护盾与伤害使用不同表现；护盾随剩余护盾值消失；远程攻击具有正确轨迹。
- 不用静止攻击姿态作为待机。脚底对齐，按人体高度校准比例，不按透明画布大小校准。
- 主城背景与点击位置使用同一坐标系；不得为填屏拉伸人物/建筑；手机需要可发现的平移提示。
- 优先现有原创素材及本机 Blender。用户未重新授权前不调用收费素材生成服务。

### D：独立试玩 QA 负责人

- 使用隔离测试存档真实操作：取名 → 山寨 → 掌柜招募 → 英雄故事/战力 → 布阵 → 征战/爬塔 → 手动/自动战斗 → 奖励 → 刷新恢复。
- 覆盖桌面、手机竖屏与横屏及音乐/音效分别切换；检查普通体力 2、精英 5、上限 100，远程射程/弹道、开局增益、无误伤、Boss 与奖励扣费不重复。
- 可直接向 A/B/C 提缺陷并推动修复复测；不得修改生产代码。仅写 tests/qa-002*、assets/releases/QA-002/ 和本任务交接单。
- 不触碰用户真实存档。缺少真实浏览器操作或证据标 BLOCKED；测试通过不等于美术通过，不以像素数量代替看图，不虚报文件、截图或录屏存在。

### Codex：要求、审美与最终独立验收负责人

- 根据最终集成提交独立检查，不以 A/B/C 自报通过替代验证。
- 检查桌面、手机竖屏与横屏；首次取名、改名、旧档恢复、招募、布阵、手动/自动战斗、结算和刷新恢复。
- 检查角色待机、比例、命中方向、护盾与法术区别、字号、遮挡、触控区域和地图覆盖。
- 交付 PASS / FAIL / BLOCKED。缺少真实浏览器画面或环境时列为 BLOCKED，不能宣称视觉通过。
- 每条缺陷须有任务 ID、复现步骤、预期/实际、证据、严重度、归属、复测结果。
- 用户已允许向参与 AI 反馈本项目缺陷；只能使用实际可用且明确指定的软件接口。接口未连接时生成退回单由用户转交，不声称已发送。

## 并发和保护规则

1. A 给每个 AI 分配独立分支和独立工作目录；若做不到，采用串行交接。同一文件同一时间仅一人编辑。本轮直接使用同目录：只读调查可并行，A 通过实际消息依次释放写权限，串行提交，仅提交已核实的任务文件。不得把共享目录误称独立分支或独立工作区。
2. 开工前记录 git status、基线提交。不得覆盖不属于自己任务的未提交修改。
3. 禁止 git reset --hard、git clean、强推、删除旧素材、清空用户存档、批量格式化整个项目。
4. 禁止修改父目录的 app.*、assets/、godot/、NewProject/、pinngoo-studio/、.venv/、系统配置、凭据及全局技能。
5. tests/ 可增加本任务测试；已有断言不得删除、跳过、降阈值来换取通过。确需变更由 A 说明行为变更并交 Codex 检查。
6. 不自动上架、部署、发布、购买、调用收费服务或向无关第三方发送项目资料。
7. 数值、存档键、资源路径、函数签名变更须事先写接口变更说明，A 负责兼容旧存档。
8. 每次交付必须更新相关测试并创建对应 Git commit，只提交自己的文件。

## 工作流

用户目标 → A 派单与接口约定 → A/B/C 在各自范围实现 → 相关测试与对应提交 → A 集成并运行全套测试 → D 独立试玩与缺陷复测 → Codex 最终独立审美和技术验收。
